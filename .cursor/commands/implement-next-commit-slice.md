# 次のコミット区切りまで実装する

`@AGENTS.md` と `docs/` を正本に、**次のコミットに収まる大きさ**まで実装する。全体を一気に完成させない。

**まだコミットしない**（ユーザーが明示するまで `git commit` / `git push` しない）。

## 手順

1. 現状を把握する（読み取り中心）:
   - `git status` / `git log -5 --oneline`
   - `@AGENTS.md` の必須振る舞い・技術方針
   - `@docs/architecture.md` の「導入済み / 未実装」
   - `@docs/domain-model.md`（型を触る場合）
2. **次の 1 区切り**を決める。目安:
   - レビュー・動作確認できるまとまり（例: 平面キャンバス、JSON 保存、縮尺校正、立面、のいずれか）
   - 依存が少ない順。未着手なら「必須のうち、土台の次に効く 1 機能」
   - 1 区切りに複数の大きな機能を混ぜない
3. 決めた区切りを短くユーザー向けに宣言してから実装する（何を含み、何を次に残すか）
4. 実装する:
   - 変更は依頼範囲（その区切り）に限定する
   - UI 文言は分かりやすくする。実装途中の内部事情を画面に出さない
   - ブラウザへのプロジェクト自動保存はしない（AGENTS どおり）
   - 依存追加が必要なら、その区切りに必要なものだけ（基本 latest）
5. 区切りの終わりに確認する:
   - `npm run build`（または Compose 経由の同等）が通ること
   - 可能なら `docker compose run --rm web npm run format`
6. 完了報告は次の形式にする（余計な前置きは不要）

## 出力フォーマット

### この区切りでやったこと

- （箇条書き）

### まだ次の区切り

- （残っている必須機能のうち、今回やらなかったもの）

### 確認方法

- （ローカルでの見方。例: `docker compose up` と操作手順）

## やらないこと

- ユーザーが明示していないコミット・プッシュ
- 区切りを越えた大きなリファクタや無関係な docs の書き換え
- 「全部できた」体で未実装を隠すこと
